# عیب‌یابی

[فهرست مستندات](README.md)

## مستندات باز نمی‌شود یا خالی است

ابتدا مطمئن شوید نسخهٔ جدید ساخته و فرآیند تولید با همان خروجی جایگزین شده است. `/docs` باید HTML و `/docs/openapi.json` باید JSON بدهد. اگر یک صفحهٔ HTML برای JSON دریافت می‌کنید، rewrite پراکسی یا نسخهٔ قدیمی را بررسی کنید.

اگر فایل Swagger 404 است، `npm run docs:prepare` و سپس ساخت را اجرا کنید و خروجی standalone را کامل منتقل کنید. اجرای معمول `npm run dev` و هر دو build آماده‌سازی را خودکار انجام می‌دهند. فایل‌های `public/docs/swagger/` به‌درستی در Git نیستند و از dependency نسخه‌ثابت ساخته می‌شوند. صفحه به اینترنت CDN وابسته نیست.

اگر مسیرهای API دیده می‌شوند اما Execute به خطا می‌خورد، status همان درخواست را بررسی کنید؛ ورود به صفحهٔ docs به معنی ورود حساب نیست. از `/login` همان دامنه وارد و به مستندات برگردید. کلید Bearer کار اعلان، جایگزین کوکی کاربر نیست. برای اسکنر `X-Scanner-Key` لازم است.

## 403 برای درخواست نوشتن

هدر Origin را با مبدأ درخواست و `APP_ORIGIN` مقایسه کنید. `localhost` و `127.0.0.1`، HTTP و HTTPS و درگاه‌های مختلف مبدأهای متفاوت‌اند. Origin غایب در curl رد می‌شود. پشت پراکسی، Host و X-Forwarded-Proto باید صحیح باشند. سپس نقش و مالکیت را بررسی کنید؛ مدیر لزوماً میزبان نیست و میزبان به رویداد میزبان دیگر دسترسی ندارد.

## 401 یا کوکی ناپایدار

انقضای نشست، خروج و بازیابی رمز می‌توانند نشست را حذف کنند. در HTTPS بررسی کنید کوکی Secure صادر و پراکسی درست تشخیص داده شود. کوکی HttpOnly در JavaScript قابل خواندن نیست؛ این رفتار عادی است. ذخیره/ارسال cookie jar در curl را جداگانه بررسی کنید. مقدار hg_session باید هگز ۶۴ نویسه باشد.

## 503 و سلامت ناموفق

در Node، DATABASE_PATH باید مطلق، پوشه قابل نوشتن و migrationها اعمال‌شده باشند. در Workers binding با نام DB لازم است. نبود جدول events باعث شکست health می‌شود. اجرای اسکریپت مهاجرت بدون صادرکردن env از فایل نیز خطا می‌دهد. سرویس موجود را به پایگاه آزمایشی هدایت نکنید.

health سالم لزوماً به معنی تنظیم SMS/پرداخت/ایمیل نیست. برای پیامک، کلید و قالب کاوه‌نگار و OTP_SECRET حداقل ۳۲ نویسه؛ برای پرداخت Merchant ID و APP_ORIGIN با HTTPS؛ برای ایمیل کلید Resend، فرستندهٔ معتبر و EMAIL_TOKEN_SECRET لازم‌اند. پیام کاربر ممکن است کلی باشد؛ زمان خطا و log سرویس را بدون انتشار رازها بررسی کنید.

## migration تغییرکرده

خطای checksum یعنی فایل قبلاً اعمال‌شده با محتوای ثبت‌شده فرق دارد. جدول migration را دست‌کاری نکنید تا خطا ناپدید شود. نسخهٔ صحیح فایل را بازیابی و تغییر جدید را در migration بعدی ارائه کنید. برای بازگردانی ناسازگار، برنامه را متوقف و پایگاه/رسانهٔ هم‌نسخه را طبق [بازیابی Docker](docker.md) برگردانید.

## ظرفیت، مهلت و پرداخت

409 رزرو می‌تواند ناشی از پایان ثبت‌نام، ظرفیت، requestKey تکراری با انتخاب متفاوت یا وضعیت نامناسب باشد. زمان سرور معیار است. پایان مهلت hold لزوماً status را به مقدار تازه تغییر نمی‌دهد؛ `expires_at` را بخوانید.

پس از پاسخ نامعلوم پرداخت، شناسهٔ سفارش و requestKey را حفظ و وضعیت را بررسی کنید؛ درخواست جدید با کلید تازه می‌تواند سفارش دیگری بسازد. `paid_unfulfilled` پرداختِ دریافت‌شده با رزرو نهایی‌نشده است؛ آن را به‌عنوان پرداخت ناموفق معمول گزارش نکنید. لغو پولی/بازپرداخت خودکار در API فعلی وجود ندارد.

## فایل و تصویر

413 ممکن است در پراکسی یا برنامه رخ دهد. هر تصویر ۵ MiB، مجموع تصاویر ۲۰ MiB و بدنهٔ multipart حداکثر ۲۱ MiB است. برای آواتار/جلد مقاله `data={}` و دقیقاً یک cover بفرستید. پسوند فایل کافی نیست؛ باینری معتبر و MIME سازگار لازم‌اند. MEDIA_PATH یا BUCKET و ارجاع جدول رسانه را بررسی کنید؛ حذف فایل قدیمی بدون توجه به snapshot پشتیبان مناسب نیست.

## اعلان ارسال نمی‌شود

ابتدا اجرای منظم job و نتیجهٔ شمارش آن را بررسی کنید. سپس configured، رضایت کاربر، ایمیل تأییدشده یا نشست فعال مرورگر، زمان ایجاد اشتراک و وضعیت خود اعلان را ببینید. اعلان قدیمی‌تر از رضایت/اشتراک، خوانده‌شده، نامرتبط یا مربوط به رزرو لغوشده عمداً ارسال نمی‌شود. قبول‌شدن توسط ارائه‌دهنده تضمین نمایش در مرورگر یا inbox نیست. جزئیات در [اعلان‌ها](notifications.md).

## نقشه یا ساخت متفاوت

اگر MAP_TILE_URL تنظیم شده، هر سه متغیر سرویس باید معتبر باشند. نبود مختصات رویداد یا اختلال کاشی با فهرست رویدادها یک مسئله نیست. از URL دلخواه به‌عنوان پراکسی سروری استفاده نکنید؛ [نقشه](map-provider.md).

اگر آزمون runtime اشتباه اجرا شده، ببینید آخرین build کدام محیط بوده است. build:node و build خروجی مشترک دارند. برای Workers، MVP_RUNTIME=node را از محیط حذف کنید. هشدار اندازهٔ chunk یا هشدارهای موجود img در lint به‌تنهایی شکست ساخت نیستند؛ exit code و خطای واقعی را بررسی کنید.
