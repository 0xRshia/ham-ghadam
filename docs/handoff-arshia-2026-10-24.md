# تحویل تغییرات فرانت به آرشیا — ۲۴ اکتبر ۲۰۲۶

شاخهٔ تحویل `frontend-arad` و مقصد PR برابر `main` است؛ ادغام، تأیید بخش‌های سرور و استقرار با آرشیا است. این تحویل هیچ تغییر مستقیمی روی سرور اصلی ایجاد نکرده است.

## تغییرات قابل بازبینی

- فیلد اینستاگرام در پنل سریع و لینک آن در جزئیات رویداد.
- لوگو و لوگوتایپ ارسالی کارفرما در آیکون مرورگر، خوشامدگویی، هدر و پاورقی.
- زمینهٔ تیرهٔ تاریخ کارت‌ها، شفافیت یکسان و بلر ملایم ۳ پیکسلی تاریخ و کادر اطلاعات.
- پنجرهٔ انتخاب نوع بلیت پیش از تعداد، حفظ جریان مستقیم تک‌نوع و نمایش قیمت قبلی/درصد/قیمت نهایی.
- کاهش فاصلهٔ انتخاب شهر تا انتخاب موقعیت در نقشه به حدود ۱۴ پیکسل.

## کارهای آرشیا پیش از ادغام و استقرار

- [ ] قرارداد و پیاده‌سازی همراه این تغییرات برای API و داده را بازبینی و تأیید یا با پیاده‌سازی خود جایگزین کند: `events.instagram_url` و `events.original_price` و `event_ticket_tiers.original_price`. کد پشتیبان در PR آماده است؛ تأیید سرور و اجرای آن به آرشیا تحویل می‌شود. تغییر نام یا شکل این فیلدها باید با فرانت هماهنگ شود.
- [ ] پیش از انتشار، پشتیبان سازگار پایگاه و رسانه تهیه و مهاجرت‌های اعمال‌نشده را به ترتیب ژورنال اجرا کند؛ دو مهاجرت تازهٔ این PR، `0018_event_instagram` و `0019_ticket_discount` هستند. نمونهٔ اجرای Node مطابق راهنمای استقرار: `npm run db:migrate:node` با متغیرهای واقعی محیط همان سرور. برای Workers/D1 از مسیر استقرار همان محیط استفاده شود.
- [ ] تأیید کند که `price` مبلغ نهایی پرداخت باقی می‌ماند و `original_price` فقط قیمت قبلی نمایش است؛ رزرو و snapshot خریدهای قبلی تغییر نمی‌کنند. مقادیر قبلی نامعتبر رد می‌شوند، نه اینکه قیمت نهایی از آن‌ها ساخته شود.
- [ ] بعد از استقرار، ذخیره/بازخوانی اینستاگرام و تخفیف از `/fast`، نمایش عمومی، انتخاب نوع/تعداد و مبلغ سروری خرید را روی محیط مقصد بررسی کند. داده‌های دموی این بررسی فقط محلی‌اند و همراه کد منتشر نمی‌شوند.
- [ ] PR را پس از بازبینی به `main` ادغام و استقرار را از نسخهٔ تأییدشده انجام دهد. متغیر محیطی جدیدی برای این قابلیت‌ها لازم نیست؛ کلیدها، `.env`، پایگاه و پشتیبان در Git قرار نمی‌گیرند.

## مورد باز کاوه‌نگار

طبق آخرین اطلاعات موجود از تیکت، کاوه‌نگار برای تأیید قالب OTP مدرک اینماد، پروانهٔ کسب یا سامان‌دهی خواسته است و مالک اعلام کرده فعلاً مدرکی وجود ندارد. آرشیا/مالک حساب باید دربارهٔ مدرک جایگزین با پشتیبانی هماهنگ کند و نام سایت/قالب و وضعیت تأیید را در پنل بررسی کند. در این نوبت قالب ویرایش یا دوباره ارسال نشده و فعال‌بودن OTP تولید تأیید نشده است.

## محدودهٔ بررسی

بررسی‌ها روی Node/SQLite و مرورگر localhost انجام شده‌اند؛ موفقیت آن‌ها به معنای تأیید محیط تولید یا Workers/D1 نیست. اصلاح RSC از PR #9 آرشیا دریافت شده و تغییر تکراری سرویس پنل حذف شده است.
