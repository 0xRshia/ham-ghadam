# مدیریت دستی رویدادها

[فهرست مستندات](README.md) · [قرارداد API](openapi.json)

پنل `/fast` همهٔ رویدادها، از جمله پیش‌نویس‌ها و رویدادهای گذشته را مدیریت می‌کند. ورود آن مستقل از حساب مشتری، میزبان و مدیر محتوای سایت است. رابط فارسی، راست‌به‌چپ و سازگار با موبایل و تم روشن/تیره است.

## راه‌اندازی

۱. وابستگی‌ها را نصب و مهاجرت‌های جدید را روی پایگاه مقصد اعمال کنید. Node از `npm run db:migrate:node` و Workers از گردش مهاجرت موجود D1 استفاده می‌کند. مهاجرت `0016_fast_admin` جدول نشست مستقل و نسخهٔ اطلاعات رویداد را اضافه می‌کند. پیش از تغییر پایگاه موجود، پشتیبان پایگاه و رسانه تهیه کنید.

۲. در محیط توسعهٔ مخزن فرمان زیر را اجرا کنید. ورودی تعاملی رمز نمایش داده نمی‌شود و رمز باید ۱۲ تا ۱۲۸ نویسه باشد. هش تولیدشده فقط در تنظیمات محرمانهٔ سرور قرار می‌گیرد:

```sh
npm run fast:password
```

۳. `FAST_ADMIN_USERNAME` و `FAST_ADMIN_PASSWORD_HASH` را در فایل env نادیده‌گرفته‌شدهٔ Node یا secretهای Workers تنظیم و فرآیند را دوباره اجرا کنید. هش را در فایل shell/env داخل **تک‌نقل‌قول** قرار دهید؛ نویسه‌های `$` بخشی از قالب scrypt هستند و نباید تفسیر شوند. رمز خام، هش واقعی و کوکی را در Git، log یا متغیرهای `NEXT_PUBLIC_*` قرار ندهید. نام کاربری نمونه یا رمز پیش‌فرضی وجود ندارد.

۴. برای اتصال رویداد به حساب برگزارکننده، حساب واقعی در `users` و شمارهٔ مجاز در `HOST_PHONES` لازم است؛ نیازی به رویداد منتشرشدهٔ قبلی ندارد. می‌توانید به‌جای انتخاب حساب، نام برگزارکننده را آزادانه بنویسید. نام مستقل فقط روی همان رویداد ذخیره می‌شود؛ حساب، پروفایل عمومی یا مجوز میزبان نمی‌سازد و مدیریت رویداد در `/fast` می‌ماند.

۵. `/fast/login` را باز کنید. نبود نام کاربری یا هش معتبر، صفحهٔ راه‌اندازی و خطای 503 API ایجاد می‌کند؛ هیچ ورود جایگزینی فعال نمی‌شود.

## استفاده

فهرست `/fast` جست‌وجوی عنوان یا شهر، فیلتر برگزارکننده و وضعیت و صفحه‌بندی ۲۰تایی از صفحهٔ یک دارد. `/fast/events/new` ساخت و `/fast/events/[id]` ویرایش است. رویداد جدید با اطلاعات واقعی کامل به‌صورت پیش‌نویس ذخیره می‌شود؛ انتشار اقدام جداگانه است.

فیلدها شامل عنوان، توضیح، دسته، برگزارکننده، محل، نشانی اختیاری، شهر، پیوند مکان، تاریخ و ساعت شروع/پایان، مهلت ثبت‌نام، قیمت تومان و ظرفیت اختیاری‌اند. تاریخ‌ها شمسی، زمان‌ها به وقت تهران و کنترل‌های زمان پنج‌دقیقه‌ای هستند. تاریخ پایان مستقل است و رویداد شبانه یا چندروزه پشتیبانی می‌شود. زمان رویداد گذشته اگر تغییر نکند مانع اصلاح توضیح یا تصویر نیست.

جلد اختیاری و حداکثر شش تصویر گالری قابل افزودن، حذف، جایگزینی و مرتب‌کردن‌اند. هر فایل JPEG/PNG/WebP واقعی تا ۵ MiB و مجموع فایل‌های جدید و نگه‌داشته‌شده تا ۲۰ MiB مجاز است. سقف multipart برابر ۲۱ MiB است. محدودیت ابعاد و رد SVG/انیمیشن مطابق [امنیت](security.md) باقی است. سرور پیوند مکان یا رسانهٔ خارجی را برای استخراج تصویر یا مختصات واکشی نمی‌کند.

پس از ذخیرهٔ اولیه، فرم‌های ردهٔ بلیت و برنامه در همان صفحه در دسترس‌اند. قواعد ظرفیت و نگهداری ردهٔ غیرفعال، برنامهٔ حداکثر ۲۴بخشی، ویدیوی HTTPS و سری تاریخ‌ها با پنل میزبان مشترک‌اند. هر بخش دکمهٔ ذخیرهٔ خودش را دارد. ابتدا تغییرات اطلاعات اصلی را ذخیره کنید تا بخش‌های پیشرفته فعال شوند.

در فیلد برگزارکننده، نام یا شماره را جست‌وجو کنید و از پیشنهادها انتخاب کنید. جست‌وجو تفاوت ی/ي، ک/ك و ارقام فارسی/عربی را نادیده می‌گیرد. فقط انتخاب صریح پیشنهاد، حساب را متصل می‌کند؛ تایپ، حتی با نام یکسان، نام مستقل باقی می‌ماند. تغییر متن پس از انتخاب، اتصال را پاک می‌کند. نام مستقل باید پس از trim بین ۱ تا ۱۰۰ نویسه و بدون نویسهٔ کنترلی باشد. نبود حساب برگزارکننده مانع ذخیره نیست.

در API، `host_id` معتبر همراه `organizer_name` حذف‌شده/null/خالی، یا `host_id=null` همراه `organizer_name` غیرخالی ارسال می‌شود. پاسخ جزئیات نام مستقل را برمی‌گرداند؛ فهرست `/fast` نام نمایشی هر دو حالت را در `organizer_name` دارد. در سایت نام مستقل متن ساده است، بدون لینک پروفایل یا دنبال‌کردن. بلیت، برنامه و ویدیو در `/fast` کار می‌کنند؛ سری رویداد نیازمند حساب متصل است.

## اینستاگرام رویداد

اینستاگرام رویداد اختیاری است؛ نام کاربری با یا بدون `@` یا لینک پروفایل پذیرفته و در `instagram_url` به شکل `https://www.instagram.com/username/` ذخیره می‌شود. لینک پست/استوری، دامنهٔ دیگر، اعتبارنامه و نام نامعتبر رد می‌شوند. خالی یا null مقدار را حذف می‌کند؛ نبود فیلد در درخواست ویرایش مقدار قبلی را حفظ می‌کند. لینک در جزئیات عمومی همان رویداد نمایش داده می‌شود و حساب یا مجوز میزبان نمی‌سازد. مهاجرت `0018_event_instagram` پیش از اجرای نسخهٔ جدید لازم است.

## محدودیت ویرایش و حذف

در فرم رویداد و ویرایش نوع بلیت، «قیمت قبل از تخفیف» اختیاری است؛ قیمت معمولی همان مبلغ نهایی خرید است. قیمت قبلی باید عدد صحیح بیشتر از قیمت نهایی و حداکثر ۱۰۰ میلیون تومان باشد؛ خالی‌کردن آن تخفیف نمایشی را حذف می‌کند. مهاجرت `0019_ticket_discount` پیش از استقرار لازم است.

- پس از وجود **هر رکورد رزرو**، برگزارکننده (حساب یا نام مستقل)، نام محل، نشانی، شهر، پیوند/مختصات مکان و زمان شروع/پایان قفل‌اند؛ حتی اگر آن رزرو بعداً لغو یا منقضی شود. این کنترل در همان دستور نوشتن SQL انجام می‌شود.
- توضیح، عنوان، دسته، تصاویر، انتشار، قیمت و ظرفیت امن قابل ویرایش‌اند. ظرفیت کمتر از بلیت‌های تأییدشده و holdهای معتبر پذیرفته نمی‌شود. قیمت و عنوان ردهٔ ذخیره‌شده در سفارش قبلی تغییر نمی‌کند.
- تاریخ تازه نباید بخش‌های برنامهٔ ذخیره‌شده را خارج از بازهٔ رویداد قرار دهد. ابتدا برنامه را اصلاح کنید.
- پیش از رزرو، تغییر برگزارکننده مجاز است؛ عضویت سری پاک و کلید اسکنر قبلی باطل می‌شود. دسترسی میزبان قبلی نیز در سرور و هنگام نوشتن بررسی می‌شود.
- حذف دائمی فقط برای رویداد فاقد سابقهٔ رزرو و نظر مجاز است؛ در سایر موارد انتشار را متوقف کنید. رزرو، رسید و بلیت موجود با توقف انتشار حذف نمی‌شوند.
- نسخهٔ قدیمی ویرایش با 409 رد می‌شود. تغییر انتشار توسط میزبان نیز نسخهٔ پنل را باطل می‌کند؛ پس از دریافت اطلاعات تازه تغییر را دوباره اعمال کنید.

اطلاعات رویداد و metadata تصاویر در batch اتمی ذخیره می‌شوند. فایل‌های قبلی تغییرناپذیر باقی می‌مانند تا پشتیبان هم‌زمان معتبر باشد. فقط آپلود تازه‌ای که عدم commit آن اثبات شده پاک می‌شود؛ نتیجهٔ نامعلوم ذخیره‌سازی نباید باعث حذف تصویر commitشده شود.

## نشست و مجوز

کوکی `hg_fast_session` هشت ساعت اعتبار، `HttpOnly`، `SameSite=Strict` و `Path=/` دارد؛ روی HTTPS دارای `Secure` است. پایگاه فقط SHA-256 توکن و اثرانگشت اعتبارنامهٔ تنظیم‌شده را ذخیره می‌کند. خروج نشست فعلی را حذف می‌کند و تغییر نام کاربری یا هش رمز، نشست‌های قبلی را نامعتبر می‌کند. ورود با محدودیت پایدار ۳۰ تلاش در ساعت برای IP و فاصلهٔ یک ثانیه محافظت می‌شود؛ نوشتن هر نشست سقف ۱۰۰ در ساعت و فاصلهٔ ۱۰۰ میلی‌ثانیه دارد.

همهٔ APIهای `/api/fast` مجوز مستقل را بررسی می‌کنند. عملیات نوشتن Origin معتبر می‌خواهد. نشست `hg_session` یا نقش مدیر محتوا جایگزین آن نیست؛ نشست `/fast` نیز به API مشتری یا مدیریت محتوا مجوز نمی‌دهد. صفحه‌ها و پاسخ‌ها نباید در cache عمومی قرار بگیرند. صفحات پنل `noindex` هستند؛ این گزینه جایگزین احراز هویت نیست.

## آزمون

```sh
npm run build:node
npm run test:fast:node
# پس از پایان آزمون Node و در محیط ساخت Workers:
npm run build
npm run test:fast:workers
```

آزمون‌ها پایگاه و رسانهٔ موقت و حساب‌های ایزوله می‌سازند؛ هیچ پیامک یا پرداخت بیرونی ارسال نمی‌شود. ورود، Origin، انقضا، خروج، چرخش اعتبارنامه، CRUD، گالری، rollback، هم‌زمانی، قفل رزرو، ظرفیت hold، برنامه/سری و تداوم پس از restart پوشش داده می‌شوند.

## نکتهٔ طراحی (Learning Notes)

اعتبارسنجی پایه در `lib/event-input.ts`، نوشتن رده در `lib/event-tier-management.ts` و برنامه در `lib/event-program.ts` بین میزبان و پنل استفادهٔ مجدد می‌شوند. مجوز مسیرها مستقل است و نوشتن حساس، مالکیت و موجودی را در SQL دوباره بررسی می‌کند.

## اهمیت تصمیم (Why This Matters)

اطلاعات پنل مستقیماً همان رویدادهای کاتالوگ و خرید است؛ نسخهٔ موازی یا دادهٔ نمایشی وجود ندارد. قفل تغییرات رزرو و حفظ رسانهٔ تغییرناپذیر از خراب‌شدن سابقهٔ خرید، ورود شرکت‌کننده و پشتیبان جلوگیری می‌کند.

مهاجرت `0017_event_organizer_name` ستون مالک را nullable و نام مستقل را اضافه می‌کند. جدول والد رویداد بازسازی نمی‌شود تا وابستگی‌های دارای حذف آبشاری حفظ شوند. ایندکس مالک و trigger نسخه پس از کپی ستون بازسازی می‌شوند. پیش از اعمال روی تولید پشتیبان سازگار پایگاه و رسانه تهیه شود.
