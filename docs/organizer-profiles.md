# پروفایل عمومی برگزارکننده و دنبال‌شده‌ها

صفحهٔ `/organizers/[id]` با کاور `organizer.cover_image`، آواتار، نام و شمار دنبال‌کننده نمایش داده می‌شود. سه تب رویدادها، مجموعه‌ها و درباره از پاسخ فعلی `/api/organizers/{id}` ساخته می‌شوند؛ تصاویر غایب/خراب جایگزین دارند، معرفی بلند ابتدا شش خط است و با دکمه باز و بسته می‌شود. کارت رویداد تاریخ شمسی، شهر و قیمت نارنجی دارد. هیچ تلفن یا ایمیل خصوصی حساب در پروفایل عمومی نمایش داده نمی‌شود.

بازدیدکننده می‌تواند برگزارکننده را دنبال کند؛ مهمان به ورود با مسیر بازگشت هدایت می‌شود. صاحب صفحه به ویرایش حساب فعلی و مدیریت رویدادها دسترسی دارد. اشتراک‌گذاری از مرورگر و در نبود آن از کپی لینک استفاده می‌کند؛ لغو پنجرهٔ اشتراک خطا نیست. پیام‌رسانی، نشان تأیید و شبکه‌های اجتماعی ساختگی اضافه نشده‌اند.

صفحهٔ `/following` نیاز به ورود دارد. در حالت پیش‌فرض، ردیف دنبال‌شده‌ها و حداکثر هشت پیشنهاد از پاسخ فهرست فعلی نمایش داده می‌شوند؛ خود کاربر و دنبال‌شده‌ها از پیشنهادها حذف می‌شوند. ترتیب API حفظ می‌شود. گزینهٔ کشف، تمام موارد پاسخ فعلی را نشان می‌دهد؛ سقف ۱۰۰ مورد API و نبود صفحه‌بندی سرور تغییر نکرده است.

وضعیت دنبال‌کردن برای هر حساب و هر منبع در حافظهٔ مرورگر مشترک است. فقط پس از موفقیت PUT/DELETE تغییر می‌کند؛ درخواست همزمان تکراری مسدود و خطا کنار دکمه نمایش داده می‌شود. بعد از تغییر، فهرست‌ها، پیشنهادها و شمارنده‌های صفحات مرتبط بازخوانی می‌شوند. مقدار عددی یا boolean پاسخ در دکمه به boolean تبدیل می‌شود. callback قبلی مجموعه‌ها حفظ شده است.

قرارداد API و دیتابیس تغییر نکرده‌اند. کاور همچنان از دادهٔ موجود API می‌آید و آپلود مستقل ندارد. ویرایش نام، آواتار، معرفی و شهر از `/account/edit` انجام می‌شود؛ ظاهر پروفایل شخصی و فرم ویرایش بازطراحی نشده است. محدودیت فعلی بک‌اند باقی است: صفحهٔ عمومی پس از اولین رویداد منتشرشدهٔ غیرنمونه قابل دسترسی است. پاسخ 404 با توضیح و مسیر بازگشت و خطاهای دیگر با امکان تلاش دوباره نمایش داده می‌شوند.

بررسی پذیرش روی localhost با پاسخ‌های کنترل‌شدهٔ API شامل هر دو تم، عرض‌های ۳۲۰/۳۷۵/دسکتاپ، تب‌ها، معرفی بلند، تصویر خراب، دنبال‌کردن و لغو، جلوگیری از درخواست تکراری، شکست درخواست و تلاش مجدد، شمارنده، پیشنهادها، کپی لینک، صاحب صفحه، مهمان، حالت خالی و 404 است. این آزمون دادهٔ واقعی یا وضعیت حساب‌ها را تغییر نمی‌دهد. انتشار یا ادغام در این مرحله انجام نمی‌شود.
