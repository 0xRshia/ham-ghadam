# پروفایل عمومی برگزارکننده و دنبال‌شده‌ها

صفحهٔ `/organizers/[id]` با کاور `organizer.cover_image`، آواتار، نام، آیدی اینستاگرام و شمار دنبال‌کننده نمایش داده می‌شود. سه تب رویدادها، مجموعه‌ها و درباره از پاسخ `/api/organizers/{id}` ساخته می‌شوند؛ تصاویر غایب/خراب جایگزین دارند و معرفی بلند باز و بسته می‌شود. کارت رویداد تاریخ شمسی و شهر دارد و قیمت نمایش داده نمی‌شود. هیچ تلفن یا ایمیل خصوصی حساب در پروفایل عمومی نمایش داده نمی‌شود. کشف برگزارکنندگان برای مهمان نیز باز است.

بازدیدکننده می‌تواند برگزارکننده را دنبال کند؛ مهمان برای این اقدام به ورود با مسیر بازگشت هدایت می‌شود. صاحب حساب متصل به ویرایش حساب و مدیریت رویدادها دسترسی دارد. آیدی اینستاگرام ثبت‌شده در کارت، ردیف و پروفایل به نشانی ثابت HTTPS اینستاگرام پیوند دارد. اشتراک‌گذاری از مرورگر و در نبود آن از کپی لینک استفاده می‌کند؛ لغو پنجرهٔ اشتراک خطا نیست. پیام‌رسانی یا نشان تأیید ساختگی اضافه نشده است.

صفحهٔ `/following` نیاز به ورود دارد. در حالت پیش‌فرض، ردیف دنبال‌شده‌ها و حداکثر هشت پیشنهاد از پاسخ فهرست فعلی نمایش داده می‌شوند؛ خود کاربر و دنبال‌شده‌ها از پیشنهادها حذف می‌شوند. ترتیب API حفظ می‌شود. گزینهٔ کشف، تمام موارد پاسخ فعلی را نشان می‌دهد؛ سقف ۱۰۰ مورد API و نبود صفحه‌بندی سرور تغییر نکرده است.

وضعیت دنبال‌کردن برای هر حساب و هر منبع در حافظهٔ مرورگر مشترک است. فقط پس از موفقیت PUT/DELETE تغییر می‌کند؛ درخواست همزمان تکراری مسدود و خطا کنار دکمه نمایش داده می‌شود. بعد از تغییر، فهرست‌ها، پیشنهادها و شمارنده‌های صفحات مرتبط بازخوانی می‌شوند. مقدار عددی یا boolean پاسخ در دکمه به boolean تبدیل می‌شود. callback قبلی مجموعه‌ها حفظ شده است.

هویت عمومی در جدول مستقل `organizers` نگهداری می‌شود و `events.organizer_id` رویدادهای یک برگزارکننده را جمع می‌کند. آیدی اینستاگرام نرمال‌شده یکتاست؛ نام مستقل دیگر نیازمند ساخت حساب ورود نیست. حساب‌های قدیمی شناسه و دنبال‌شده‌های خود را حفظ می‌کنند. کاور همچنان از دادهٔ رویداد می‌آید و آپلود مستقل ندارد. ویرایش اطلاعات حساب متصل از مسیرهای حساب انجام می‌شود؛ ظاهر فرم شخصی بازطراحی نشده است. صفحهٔ عمومی پس از اولین رویداد منتشرشدهٔ غیرنمونه در دسترس است. پاسخ 404 توضیح و مسیر بازگشت، و خطاهای دیگر تلاش دوباره دارند. جزئیات مهاجرت و سازگاری در [حالت اطلاع‌رسانی](discovery-mode.md) است.

شناسه‌های مستقل مانند `instagram:book.club` در URL یک بار کدگذاری می‌شوند. پارامتر صفحهٔ vinext پیش از تحویل به مؤلفهٔ عمومی یک بار decode می‌شود؛ پارامتر API دوباره decode نمی‌شود. بنابراین ساخت صفحهٔ عمومی نیاز به حساب ورود جداگانه ندارد و همچنان برای پروفایل دارای رویداد منتشرشدهٔ غیرنمونه در دسترس است.

پیوند برگزارکننده در رویداد، خانه، جست‌وجو، فهرست و مجموعه، مسیر مبدأ را با `?from=` نگه می‌دارد. فلش بازگشت در حالت بارگیری، موفق، خطا و 404 به همان مسیر و فیلترهایش برمی‌گردد؛ در کلیک عادی بخش `#` نیز حفظ می‌شود. بازگشت، ورودی فعلی تاریخچه را جایگزین می‌کند تا دوباره صفحهٔ پروفایل به آن افزوده نشود. لینک مستقیم یا اشتراکی بدون مبدأ به `/events` برمی‌گردد؛ اشتراک‌گذاری پروفایل مبدأ مرور شخص را منتشر نمی‌کند. مسیر مبدأ فقط نشانی نسبی محلی با طول محدود است و مقصد بیرونی، نامعتبر یا خود همان پروفایل پذیرفته نمی‌شود. مسیرهای تو‌در‌توی پروفایل پارامتر `from` قبلی را حمل نمی‌کنند تا لینک‌ها بازگشتی و بزرگ نشوند. ورود مهمان نیز شناسهٔ namespaced و مبدأ معتبر پروفایل را حفظ می‌کند.

`npm run test:discovery` علاوه بر آزمون SQL و مهاجرت، تطبیق مسیر واقعی vinext از صفحه تا API، پنهان‌ماندن پیش‌نویس/نمونه و آزمون `tests/organizer-navigation.mjs` برای پیوند و فلش بازگشت واقعی در همهٔ حالت‌ها را اجرا می‌کند. `node tests/auth-navigation.mjs` برگشت پس از ورود و جابه‌جایی فرم‌های ورود را پوشش می‌دهد.

## تصویر واقعی برگزارکننده

بعد از ذخیرهٔ اولین رویداد یا انتخاب برگزارکنندهٔ موجود در `/fast`، بخش «تصویر پروفایل برگزارکننده» بارگذاری مستقل JPG/PNG/WebP تا ۵ مگابایت را می‌پذیرد. این بخش در ویرایشگر رویداد متصل به شیت نیز در دسترس است و همگام‌سازی عکس مشترک را بازنویسی نمی‌کند. این تصویر با تمام رویدادهای همان پروفایل مشترک است و پوستر رویداد به‌جای عکس شخص/برند استفاده نمی‌شود. تصویر حساب متصل که صاحب حساب در پروفایل خود بارگذاری کرده، اولویت دارد. در نبود تصویر معتبر، حروف نام جایگزین می‌شوند.

خواندن تصویر از هر آیدی اینستاگرام بدون اتصال حساب، API رسمی قابل اتکایی ندارد. اتصال اختیاری **Business Discovery** متا فقط برای حساب‌های حرفه‌ای قابل دسترس است و توکن Facebook Login با مجوزهای لازم و حساب حرفه‌ای متصل به Page می‌خواهد؛ حساب‌های شخصی یا خصوصی تضمین نمی‌شوند. [مستندات رسمی متا](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/business-discovery/) و [مجموعهٔ رسمی Meta در Postman](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api) مرجع راه‌اندازی‌اند. هیچ سرویس پولی، scraping بدون ورود یا عکس ساختگی جایگزین نشده است.

در صورت تنظیم هر سه متغیر بخش [پیکربندی](configuration.md#تصویر-اینستاگرام-برگزارکننده)، ویرایشگر مدیر برای پروفایل فاقد تصویر یک بار درخواست واردکردن می‌دهد؛ دکمهٔ دریافت نیز موجود است. بازدید صفحات عمومی درخواست API متا نمی‌سازد. عکس معتبر دریافت‌شده در فایل محلی Node یا R2 ذخیره می‌شود تا URL موقت CDN اینستاگرام به مرورگر وابسته نباشد. تصویر واردشده تا ۲۴ ساعت دوباره دریافت نمی‌شود؛ خطاها حداقل یک دقیقه فاصله و سقف چهار درخواست در ساعت برای هر پروفایل دارند. تغییر آیدی هنگام دریافت، یا بارگذاری دستی همزمان، اجازهٔ جایگزینی اشتباه نمی‌دهد. تصویر دستی با واردکردن خودکار بازنویسی نمی‌شود.

مهاجرت `0025_organizer_media` متادیتای تصویر مشترک را در `organizer_media` نگه می‌دارد و پشتیبان Node آن را همراه فایل‌ها کپی می‌کند. فایل قبلی برای پشتیبان‌های سازگار حذف فیزیکی نمی‌شود؛ URL قدیمی پس از تعویض/حذف پاسخ 404 دارد. `/api/organizer-media/{id}` فقط برای پروفایل عمومی منتشرشده یا نشست معتبر مدیر `/fast` تصویر می‌دهد؛ تصویر عمومی با `private, no-cache` و ETag بازاعتبارسنجی می‌شود و پیش‌نمایش خصوصی `private, no-store` است. [قواعد کش و اندازهٔ تصویر](image-delivery.md). API مدیریت `/api/fast/organizers/{id}/avatar` برای GET/PUT/POST/DELETE به همان نشست مستقل مدیر نیاز دارد؛ PUT/POST/DELETE بررسی Origin دارند.

بررسی پذیرش روی localhost با پاسخ‌های کنترل‌شدهٔ API شامل هر دو تم، عرض‌های ۳۲۰/۳۷۵/دسکتاپ، تب‌ها، معرفی بلند، تصویر خراب، دنبال‌کردن و لغو، جلوگیری از درخواست تکراری، شکست درخواست و تلاش مجدد، شمارنده، پیشنهادها، کپی لینک، صاحب صفحه، مهمان، حالت خالی و 404 است. این آزمون دادهٔ واقعی یا وضعیت حساب‌ها را تغییر نمی‌دهد. انتشار یا ادغام در این مرحله انجام نمی‌شود.
