# بهینه‌سازی و کش تصویر

`components/ui/responsive-image.tsx` اندازهٔ نمایش را با `sizes` و نسخه‌های `srcset` به مرورگر می‌دهد. تصویر اصلی جزئیات و نخستین کارت مهم `eager/high` هستند؛ تصاویر دیگر با lazy loading و decoding غیرهم‌زمان بارگیری می‌شوند. چیدمان، نسبت تصویر و برش CSS حفظ شده‌اند. لینک گالری همچنان فایل اصلی را باز می‌کند. تصاویر خارجی و پیش‌نمایش‌های blob از مسیر اصلی خود خوانده می‌شوند؛ سرور پراکسی URL دلخواه نیست.

## دارایی‌های ثابت

`npm run images:optimize` بنرها، شش تصویر سه‌بعدی و عکس‌های محلی را از فایل اصلی به WebP تبدیل می‌کند. فایل‌های اصلی حفظ می‌شوند. نسخه‌های نمایشی در `public/optimized/` و نگاشت آن‌ها در `lib/static-image-manifest.json` قرار دارند و همراه کد نگهداری می‌شوند؛ پس از تغییر اصل تصویر این فرمان را اجرا کنید. نام هر خروجی شامل هش محتوای آن است تا تغییر تصویر نشانی تازه بسازد. اندازهٔ نسخهٔ بزرگ هر یک از ۱۹ تصویر در مجموع از ۸٬۲۱۶٬۸۹۶ به ۷۴۴٬۵۱۸ بایت کاهش یافت (۹۱٪). این عدد اندازهٔ فایل است، نه اندازه‌گیری زمان بارگیری صفحه.

نسخه‌های ثابت در Node و Workers قابل استفاده‌اند. Node برای دارایی عمومی یک ساعت cache و ETag فراهم می‌کند؛ هش نشانی مانع نمایش نسخهٔ قدیمی پس از تغییر manifest می‌شود.

## رسانهٔ بارگذاری‌شده

در ساخت Node، مسیرهای موجود `/api/media/{id}`، `/api/profile-media/{id}`، `/api/organizer-media/{id}` و `/api/article-media/{id}` پارامترهای `w` و `v=1` را می‌پذیرند. عرض‌های مجاز ۹۶، ۱۹۲، ۳۸۴، ۶۴۰، ۹۶۰ و ۱۴۴۰ هستند. Sharp نسخهٔ WebP با کیفیت ۸۰، جهت EXIF درست و بدون بزرگ‌کردن منبع کوچک تولید می‌کند. شفافیت و انیمیشن حفظ می‌شوند. حذف پارامترها همان فایل اصلی را برمی‌گرداند. هیچ migration یا بازنویسی فایل اصلی لازم نیست؛ تصاویر قبلی هم در اولین درخواست تبدیل می‌شوند.

خروجی در `MEDIA_PATH/.image-cache` نگهداری می‌شود. سقف کش هر فرآیند/volume برابر ۲۵۶ MiB است و قدیمی‌ترین خروجی‌ها هنگام درج حذف می‌شوند. تبدیل‌ها ترتیبی‌اند؛ درخواست‌های هم‌زمان برای یک تصویر مشترک‌اند و حداکثر ۱۶ تبدیل در صف می‌ماند. ورودی بالاتر از ۴۰ میلیون پیکسل پردازش نمی‌شود. حذف پوشهٔ کش فقط باعث تولید دوباره می‌شود. فایل‌های اصلی و جدول رسانه منبع حقیقت هستند؛ مجوز پیش از خواندن کش بررسی می‌شود.

- تصویر رویداد همان سیاست عمومی یک‌سالهٔ immutable را حفظ می‌کند.
- تصویر پروفایل، برگزارکننده و جلد مقالهٔ عمومی `private, no-cache` و `ETag` دارند: مرورگر بایت‌ها را ذخیره می‌کند ولی پیش از استفاده مجدد مجوز و وجود رکورد بررسی می‌شود. پاسخ ۳۰۴ بدنه ندارد.
- پیش‌نمایش پیش‌نویس `private, no-store` دارد. درخواست شرطی نمی‌تواند احراز هویت یا انتشار را دور بزند.
- تغییر نسخهٔ تبدیل نیازمند افزایش `IMAGE_VARIANT_VERSION` است؛ تغییر یا جایگزینی رسانه شناسه/کلید جدید می‌سازد.

Workers در این مخزن Images binding ندارد. این ساخت برای رسانهٔ بارگذاری‌شده URL اصلی را تولید می‌کند و درخواست صریح resize را با ۴۰۰ رد می‌کند؛ کش مرورگر، تصاویر ثابت WebP و lazy loading همچنان فعال‌اند. Sharp فقط در سازگارساز Node وارد می‌شود و در bundle Workers نیست.

## Learning Notes

در vinext نصب‌شده، endpoint استاندارد `next/image` روی Node فایل اصلی را بازمی‌گرداند؛ صرف جایگزینی تگ تصویر یا تنظیم TTL باعث کوچک‌شدن فایل نمی‌شود. بنابراین تبدیل در مرز ذخیره‌سازی موجود انجام می‌شود. APIهای تبدیل از [مستندات Sharp](https://sharp.pixelplumbing.com/api-resize/) و سورس نصب‌شده بررسی شدند؛ Context7 هنگام این تغییر به سقف سهمیه رسیده بود.

## Why This Matters

کارت کوچک دیگر پوستر چندمگابایتی دریافت نمی‌کند و درخواست تکراری هزینهٔ تبدیل دوباره ندارد. بازاعتبارسنجی تصاویر دارای وضعیت انتشار، اجازه نمی‌دهد cache عمومی یک‌ساله کنترل دسترسی پیش‌نویس را بی‌اثر کند.

## اعتبارسنجی

`npm run test:images` تبدیل واقعی، ابعاد، شفافیت، حفظ فایل اصلی، هم‌زمانی، استفادهٔ دوبارهٔ دیسک، پاسخ ۳۰۴، سیاست خصوصی و ورودی نامعتبر را می‌سنجد. `node tests/organizer-avatar.mjs` لغو انتشار با ETag قبلی را نیز بررسی می‌کند. TypeScript، lint، ساخت Node/Workers و آزمون localhost را مطابق [راهنمای آزمون](testing.md) اجرا کنید.

آزمون مرورگر ساخت Node: `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/image-browser.mjs`. این آزمون سرور و SQLite موقت خود را روی 127.0.0.1:5194 اجرا می‌کند و دریافت WebP، hero با اولویت بالا، بنر lazy، پاسخ ۳۰۴ و عرض موبایل/دسکتاپ را بررسی می‌کند.
