# پیکربندی

[فهرست مستندات](README.md)

مرجع نام تنظیمات، `cloudflare-env.d.ts`، `db/node.ts`، `vite.config.ts` و اسکریپت‌های اجراست. در Node مقدارها از `process.env` و در Workers از `cloudflare:workers` خوانده می‌شوند. `.env.example` و `.env.docker.example` قالب‌اند و حاوی اعتبارنامهٔ واقعی نیستند.

## برنامه و ذخیره‌سازی

| متغیر | کاربرد |
| --- | --- |
| `MVP_RUNTIME` | مقدار `node` برای انتخاب آداپتور SQLite هنگام توسعه/ساخت؛ Workers با مسیر پیش‌فرض ساخته می‌شود |
| `APP_ORIGIN` | مبدأ کامل و بدون مسیر؛ تولید: `https://hmghadam.com`، توسعه: `http://localhost:5173`؛ callback و بررسی Origin از آن استفاده می‌کنند |
| `DATABASE_PATH` | مسیر مطلق فایل SQLite در Node؛ پوشهٔ والد باید موجود و قابل نوشتن باشد |
| `MEDIA_PATH` | مسیر مطلق پوشهٔ تصاویر Node؛ در Docker برابر `/data/media` |
| `DB` | binding پایگاه D1 در Workers، متغیر رشته‌ای env نیست |
| `BUCKET` | binding سطل R2 در Workers، متغیر رشته‌ای env نیست |
| `HOST` / `PORT` | نشانی گوش‌دادن و درگاه standalone؛ در Docker `0.0.0.0:3000` |
| `APP_PORT` | درگاه منتشرشدهٔ Docker Compose روی میزبان؛ درگاه داخل کانتینر را تغییر نمی‌دهد |
| `APP_ENV_FILE` | فایل env سرویس Compose؛ پیش‌فرض `.env.docker`؛ با `--env-file` هماهنگ نگه دارید |
| `VINEXT_TRUST_PROXY` | در نمونهٔ Docker، فقط پشت پراکسی HTTPS قابل اعتماد برابر `1`؛ در دسترسی مستقیم `0` |
| `VINEXT_TRUSTED_HOSTS` | تنظیم نمونهٔ systemd موجود؛ نمونهٔ قدیمی `dev.rshi.info` است و باید با استقرار واقعی تطبیق داده شود |
| `BACKUP_DIRECTORY` | مسیر مطلق مقصدِ موجود برای `scripts/backup-node.mjs` |
| `NODE_ENV` | در سرویس تولید `production`؛ جایگزین غیرفعال‌کردن پرچم‌های آزمایشی نیست |

## ورود و نقش‌ها

| متغیر | کاربرد |
| --- | --- |
| `OTP_SECRET` | راز تصادفی حداقل ۳۲ نویسه برای HMAC کد پیامکی؛ برای کد آزمایشی نیز لازم است |
| `KAVENEGAR_API_KEY` | کلید سرویس کاوه‌نگار، فقط سمت سرور |
| `KAVENEGAR_TEMPLATE` | نام قالب تأییدشدهٔ پیامک کاوه‌نگار |
| `HOST_PHONES` | شماره‌های میزبان جداشده با کاما؛ با قالب نرمال `09...` و بدون فاصلهٔ داخلی |
| `FAST_ADMIN_USERNAME` | نام کاربری مستقل پنل `/fast`، فقط سمت سرور |
| `FAST_ADMIN_PASSWORD_HASH` | هش scrypt با `npm run fast:password`؛ در فایل env داخل تک‌نقل‌قول قرار گیرد؛ بدون رمز پیش‌فرض |
| `ADMIN_PHONES` | شماره‌های مدیر جداشده با کاما؛ کد آن‌ها را نرمال می‌کند |
| `TEMP_LOGIN_ENABLED` | فقط `true` مسیر ورود آزمایشی موجود را فعال می‌کند؛ تولید `false` |
| `SEED_SAMPLE_EVENTS` | فقط `true` دادهٔ نمونه را اضافه و در فهرست مربوط نمایش می‌دهد؛ تولید `false` |
| `SKIP_PAY_DEV` | فقط `true` عبور از درگاه برای توسعه را فعال می‌کند؛ تولید `false` |

### اتصال OTP کاوه‌نگار

کلید موجود پنل و نام قالب در `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` تنظیم می‌شوند؛ `OTP_SECRET` موجود برای اعتبارسنجی کدها حفظ شود. در اجرای محلی مقادیر فقط در `.env.local` نادیده‌گرفته‌شده قرار می‌گیرند؛ برای محیط اصلی، مسئول سرور باید آن‌ها را جداگانه در تنظیمات محرمانهٔ همان محیط قرار دهد. پس از تغییر، فرآیند سرور دوباره اجرا شود.

مسیر `/api/auth/request` با `verify/lookup` و پارامترهای `receptor`، `token`، `template` و `type=sms` ارسال می‌کند. متن قالب باید نام هم‌قدم و `%token` داشته باشد؛ اعتبار کد پنج دقیقه است. نام برند، دامنه و مدرک کسب‌وکار قالب باید با سایت هماهنگ و قالب در پنل تأیید شده باشد. مقدار `smsReady` فقط کامل‌بودن تنظیمات را نشان می‌دهد، نه تأیید قالب یا تحویل پیامک. موفقیت `account/info` نیز صرفاً اعتبار کلید و دسترسی سرویس را تأیید می‌کند.

آزمایش واقعی با شمارهٔ مجاز کاربر و پس از تأیید قالب انجام شود. درخواست ناموفق پیامک، challenge تازه را حذف می‌کند و کد قبلی معتبر را نگه می‌دارد. اطلاعات کلید و پاسخ حاوی دادهٔ حساب نباید در لاگ، مستندات یا Git ثبت شوند.

`isHost` و `isAdmin` در `lib/server.ts` نقش را هنگام خواندن نشست از تنظیمات فعلی می‌سازند؛ ستون role روی کاربر وجود ندارد. نقش مدیر به‌تنهایی به معنی نقش میزبان نیست.

برای ساخت یک راز جدید، خروجی این فرمان را فقط در تنظیم امن سرویس قرار دهید:

```sh
node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'
```

## پرداخت، ایمیل و اعلان

| متغیر | کاربرد |
| --- | --- |
| `ZARINPAL_MERCHANT_ID` | شناسهٔ پذیرنده؛ آمادگی پرداخت همچنین به APP_ORIGIN با HTTPS وابسته است |
| `RESEND_API_KEY` | کلید API سرویس ایمیل |
| `EMAIL_FROM` | نشانی سادهٔ فرستنده از دامنهٔ تأییدشده در Resend |
| `EMAIL_TOKEN_SECRET` | راز مستقل حداقل ۳۲ نویسه برای کد ایمیل و لینک لغو اشتراک |
| `VAPID_PUBLIC_KEY` | کلید عمومی Web Push؛ پس از اعتبارسنجی به مرورگر داده می‌شود |
| `VAPID_PRIVATE_KEY` | کلید خصوصی متناظر؛ فقط سمت سرور |
| `VAPID_SUBJECT` | نشانی تماس `mailto:` یا HTTPS اپراتور |
| `NOTIFICATION_JOB_SECRET` | راز مستقل حداقل ۳۲ نویسه برای Bearer کار زمان‌بندی |

نبودن این تنظیمات نباید با پاسخ موفق ساختگی جبران شود. APIها وضعیت `configured` یا خطای مربوط را برمی‌گردانند. تنظیم صف اعلان به معنی ایجاد scheduler نیست؛ آن را جداگانه طبق [اعلان‌ها](notifications.md) فعال کنید.

### راه‌اندازی درگاه زرین‌پال

کد اتصال در `lib/payments.ts` و مسیر برگشت در `/api/payments/callback` موجود است. پیش از تنظیم شناسهٔ پذیرنده، دامنهٔ مجاز درگاه، عنوان کسب‌وکار و محدودیت IP در پنل با سایت مقصد و IP خروجی واقعی سرور تطبیق داده شوند؛ شناسهٔ درگاه یک دامنهٔ دیگر به‌تنهایی مجوز استفاده روی هم‌قدم نیست. محدودیت IP پنل برای آزمایش محلی غیرفعال نشود.

در تنظیمات محرمانهٔ سرور هم‌قدم، `ZARINPAL_MERCHANT_ID` برابر شناسهٔ درگاه مجاز، `APP_ORIGIN=https://hmghadam.com` و `SKIP_PAY_DEV=false` قرار می‌گیرد. اگر دامنهٔ مقصد متفاوت است، Origin و مجوز درگاه باید برای همان دامنه تنظیم شوند. آدرس برگشت این نصب `https://hmghadam.com/api/payments/callback` است. مقادیر واقعی وارد Git یا متغیرهای عمومی مرورگر نمی‌شوند. Origin لوکال برای فعال‌کردن درگاه واقعی به دامنهٔ تولید تغییر نکند؛ پایگاه محلی و سرور تولید دو محیط مستقل‌اند.

مبلغ در برنامه تومان است و هنگام درخواست درگاه به ریال تبدیل می‌شود (`amount_rial` و `currency=IRR`). برگشت با `Status=OK` به‌تنهایی موفقیت نیست؛ سرور Authority و مبلغ ذخیره‌شده را با API زرین‌پال تأیید می‌کند. کدهای موفق ۱۰۰/۱۰۱ و جلوگیری از تأیید تکراری در منطق فعلی مدیریت می‌شوند. `paymentReady` تنها وجود تنظیمات پایه و HTTPS را نشان می‌دهد و اثبات اعتبار درگاه، دامنه، IP یا پرداخت موفق نیست. آزمون واقعی پس از تنظیم محیط مقصد با مبلغ و سفارش مشخص و با تأیید کاربر انجام شود.

## نقشه

| متغیر | کاربرد |
| --- | --- |
| `MAP_TILE_URL` | قالب HTTPS شامل `{z}`، `{x}` و `{y}` برای ارائه‌دهندهٔ تصویری دلخواه؛ اگر تنظیم نشود زمینهٔ مینیمال روشن/تیرهٔ OpenFreeMap استفاده می‌شود |
| `MAP_ATTRIBUTION_LABEL` | متن اعتباردهی لازم برای سرویس انتخاب‌شده |
| `MAP_ATTRIBUTION_URL` | نشانی HTTPS صفحهٔ حقوق/اعتباردهی سرویس |

هنگام تغییر سرویس هر سه مقدار لازم‌اند. URL کاشی به مرورگر داده می‌شود؛ راز سمت سرور را داخل آن نگذارید. [جزئیات نقشه](map-provider.md).

## تنظیمات ابزارها

`TEST_ORIGIN` برای تست یکپارچه‌سازی باید loopback باشد؛ پیش‌فرض `http://127.0.0.1:5188` است. اسکریپت‌های تصویری ممکن است `PLAYWRIGHT_MODULE` را برای مسیر نصب ابزار بخوانند؛ این‌ها تنظیمات محصول نیستند. متغیرهای Wrangler، Miniflare و `SITES_*` در ابزارهای ساخت برای محیط میزبانی موجود مدیریت می‌شوند؛ آن‌ها را با اعتبارنامه‌های برنامه اشتباه نگیرید.

تنظیم و آزمون پنل مستقل در [مدیریت سریع](fast-admin.md) است؛ تغییر اعتبارنامهٔ آن نشست‌های پنل را باطل می‌کند و به حساب مشتری وابسته نیست.

## همگام‌سازی شیت

`EVENT_SYNC_JOB_SECRET` راز مستقل سرور/worker با حداقل ۳۲ نویسه است. `EVENT_SYNC_IMAGE_HOSTS` فهرست اختیاری نام دقیق میزبان HTTPS تصاویر، با جداکنندهٔ کاما، افزون بر Drive عمومی است. `EVENT_SYNC_JOB_ORIGIN` فقط در فرآیند worker مبدأ job را تعیین می‌کند؛ Compose مقدار داخلی `http://app:3000` می‌گذارد و در اجرای مستقل پیش‌فرض `APP_ORIGIN` است. پیوند شیت و سال شمسی در پایگاه و `/fast` نگهداری می‌شوند؛ [قرارداد کامل](event-sheet-sync.md).
