# پیکربندی

[فهرست مستندات](README.md)

مرجع نام تنظیمات، `cloudflare-env.d.ts`، `db/node.ts`، `vite.config.ts` و اسکریپت‌های اجراست. در Node مقدارها از `process.env` و در Workers از `cloudflare:workers` خوانده می‌شوند. `.env.example` و `.env.docker.example` قالب‌اند و حاوی اعتبارنامهٔ واقعی نیستند.

## برنامه و ذخیره‌سازی

| متغیر | کاربرد |
| --- | --- |
| `MVP_RUNTIME` | مقدار `node` برای انتخاب آداپتور SQLite هنگام توسعه/ساخت؛ Workers با مسیر پیش‌فرض ساخته می‌شود |
| `APP_ORIGIN` | مبدأ کامل و بدون مسیر؛ برنامهٔ رویداد تولید: `https://app.hmghadam.com`، توسعه: `http://localhost:5173`؛ callback و بررسی Origin از آن استفاده می‌کنند |
| `DATABASE_PATH` | مسیر مطلق فایل SQLite در Node؛ پوشهٔ والد باید موجود و قابل نوشتن باشد |
| `MEDIA_PATH` | مسیر مطلق پوشهٔ تصاویر Node؛ در Docker برابر `/data/media` |
| `DB` | binding پایگاه D1 در Workers، متغیر رشته‌ای env نیست |
| `BUCKET` | binding سطل R2 در Workers، متغیر رشته‌ای env نیست |
| `HOST` / `PORT` | نشانی گوش‌دادن و درگاه standalone؛ در Docker `0.0.0.0:3000` |

| `APP_ENV_FILE` | فایل env سرویس Compose؛ پیش‌فرض `.env.docker`؛ با `--env-file` هماهنگ نگه دارید |
| `VINEXT_TRUST_PROXY` | در نمونهٔ Docker، فقط پشت پراکسی HTTPS قابل اعتماد برابر `1`؛ در دسترسی مستقیم `0` |
| `VINEXT_TRUSTED_HOSTS` | تنظیم نمونهٔ systemd موجود؛ نمونهٔ قدیمی `dev.rshi.info` است و باید با استقرار واقعی تطبیق داده شود |
| `BACKUP_DIRECTORY` | مسیر مطلق مقصدِ موجود برای `scripts/backup-node.mjs` |
| `NODE_ENV` | در سرویس تولید `production`؛ جایگزین غیرفعال‌کردن پرچم‌های آزمایشی نیست |

### اتصال OTP ایده‌کاوان

ApiKey پنل و شمارهٔ فرستنده در `IDEKAVAN_API_KEY` و `IDEKAVAN_SENDER` تنظیم می‌شوند؛ `OTP_SECRET` موجود برای اعتبارسنجی کدها حفظ شود. در اجرای محلی مقادیر فقط در `.env.local` نادیده‌گرفته‌شده قرار می‌گیرند؛ برای محیط اصلی، مقادیر در `/root/ham-ghadam/.env.docker` روی سرور قرار می‌گیرند و با انتشار بعدی یا ساخت دوبارهٔ کانتینر اعمال می‌شوند. متغیرهای قدیمی `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` دیگر خوانده نمی‌شوند. اسکریپت اعلان مرورگر کاوه‌نگار مستقل از پیامک است و در [اعلان‌ها](notifications.md) توضیح داده شده است.

مسیر `/api/auth/request` کد را بدون الگو و به صورت متن ساده با `POST https://api.m.idekavan.com/api/message/send` و هدر `X-API-Key` ارسال می‌کند. بدنه آرایه‌ای با یک پیام است؛ شماره از قالب `09…` به `989…` تبدیل می‌شود، `DataCoding=8` برای متن فارسی است و `udh` برابر شناسهٔ challenge است تا پیام در پنل قابل پیگیری باشد. متن پیام در `faContent.otpSmsText` قرار دارد. در مبدأ HTTPS بدون پورت سفارشی، آخرین خط به شکل `@app.hmghadam.com #123456` است؛ دامنه از Origin مرورگر پس از بررسی `sameOrigin` گرفته می‌شود و در staging برابر `stage.hmghadam.com` خواهد بود. این قالب همراه `autocomplete="one-time-code"` پیشنهاد کد روی صفحه‌کلید آیفون را ممکن می‌کند. Android پشتیبانی‌شده پیش از ارسال پیامک با WebOTP منتظر کد می‌ماند؛ فقط با تأیید مرورگر فیلد پر می‌شود و تأیید ورود همچنان با کاربر است. انصراف، برگشت، ارسال مجدد، تایپ دستی یا خروج از صفحه انتظار قبلی را لغو می‌کند. وب‌سایت رفتار لمس/کپی داخل برنامهٔ Messages را کنترل نمی‌کند.

اگر حساب فرستنده دامنه را لینک تشخیص دهد و صریحاً `-21` بدهد، فقط همان پیام ردشده یک‌بار با متن ساده و همان کد بازفرستاده می‌شود تا ورود قطع نشود. خطای شبکه، timeout یا کدهای دیگر retry نمی‌شوند. این fallback تضمین AutoFill دامنه‌ای ندارد؛ تأیید نهایی با SMS واقعی و آیفون/Android لازم است. اعتبار کد پنج دقیقه است. مرجع قالب: [Apple](https://developer.apple.com/documentation/security/enabling-autofill-for-domain-bound-sms-codes) و [Chrome WebOTP](https://developer.chrome.com/docs/identity/web-apis/web-otp).

```json
[{ "SourceAddress": "9890006763", "DestinationAddress": "989123456789", "MessageText": "هم‌قدم\nکد ورود شما: 123456\n…", "DataCoding": 8, "udh": "<challenge id>" }]
```

ارسال فقط وقتی موفق است که پاسخ HTTP موفق، `succeeded` برابر `true`، `resultCode` برابر `100` و اولین عضو `data` شناسهٔ پیام باشد. اگر آن عضو کد خطای ارسال (مثل `0` یا `-1`) باشد، پیام ارسال‌نشده حساب می‌شود. در هر شکست، وضعیت HTTP، `resultCode` و کد پیام (بدون کلید) در لاگ سرور ثبت می‌شود؛ مثلاً `-1` کمبود اعتبار، `-11` فرستندهٔ نامعتبر و `-18` IP ثبت‌نشده است. فهرست کامل در مستند ایده‌کاوان، بخش «کدهای خطا در هنگام ارسال» و «کدهای بازگشتی API» آمده است.

پیش از استفادهٔ عملیاتی:

- IP خروجی هر محیط باید با نامهٔ مکتوب به ایده‌کاوان اعلام شود؛ فعلاً فقط IP سرور `91.220.113.109` ثبت شده و درخواست از سیستم توسعه خطای 401 می‌گیرد.
- نام هدر در PDF ایده‌کاوان به شکل `Key-API-X` چاپ شده که جابه‌جایی راست‌به‌چپ است؛ نام درست `X-API-Key` از IP ثبت‌شدهٔ سرور با `GET /api/user/userinfo` تأیید شده است.
- حساب پیش‌پرداخت باید اعتبار کافی داشته باشد؛ مقدار آن با `GET /api/user/userinfo` قابل بررسی است.

مقدار `smsReady` فقط کامل‌بودن تنظیمات را نشان می‌دهد، نه اعتبار حساب، ثبت IP یا تحویل پیامک. درخواست ناموفق پیامک، challenge تازه را حذف می‌کند و کد قبلی معتبر را نگه می‌دارد. اطلاعات کلید و پاسخ حاوی دادهٔ حساب نباید در لاگ، مستندات یا Git ثبت شوند.

`isHost` و `isAdmin` در `lib/server.ts` نقش را هنگام خواندن نشست از تنظیمات فعلی می‌سازند؛ ستون role روی کاربر وجود ندارد. نقش مدیر به‌تنهایی به معنی نقش میزبان نیست.

برای ساخت یک راز جدید، خروجی این فرمان را فقط در تنظیم امن سرویس قرار دهید:

```sh
node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'
```

### راه‌اندازی درگاه زرین‌پال

کد اتصال در `lib/payments.ts` و مسیر برگشت در `/api/payments/callback` موجود است. پیش از تنظیم شناسهٔ پذیرنده، دامنهٔ مجاز درگاه، عنوان کسب‌وکار و محدودیت IP در پنل با سایت مقصد و IP خروجی واقعی سرور تطبیق داده شوند؛ شناسهٔ درگاه یک دامنهٔ دیگر به‌تنهایی مجوز استفاده روی هم‌قدم نیست. محدودیت IP پنل برای آزمایش محلی غیرفعال نشود.

در تنظیمات محرمانهٔ سرور هم‌قدم، `ZARINPAL_MERCHANT_ID` برابر شناسهٔ درگاه مجاز، `APP_ORIGIN=https://hmghadam.com` و `SKIP_PAY_DEV=false` قرار می‌گیرد. اگر دامنهٔ مقصد متفاوت است، Origin و مجوز درگاه باید برای همان دامنه تنظیم شوند. آدرس برگشت این نصب `https://hmghadam.com/api/payments/callback` است. مقادیر واقعی وارد Git یا متغیرهای عمومی مرورگر نمی‌شوند. Origin لوکال برای فعال‌کردن درگاه واقعی به دامنهٔ تولید تغییر نکند؛ پایگاه محلی و سرور تولید دو محیط مستقل‌اند.

مبلغ در برنامه تومان است و هنگام درخواست درگاه به ریال تبدیل می‌شود (`amount_rial` و `currency=IRR`). برگشت با `Status=OK` به‌تنهایی موفقیت نیست؛ سرور Authority و مبلغ ذخیره‌شده را با API زرین‌پال تأیید می‌کند. کدهای موفق ۱۰۰/۱۰۱ و جلوگیری از تأیید تکراری در منطق فعلی مدیریت می‌شوند. `paymentReady` تنها وجود تنظیمات پایه و HTTPS را نشان می‌دهد و اثبات اعتبار درگاه، دامنه، IP یا پرداخت موفق نیست. آزمون واقعی پس از تنظیم محیط مقصد با مبلغ و سفارش مشخص و با تأیید کاربر انجام شود.

## تصویر اینستاگرام برگزارکننده

بارگذاری دستی تصویر برگزارکننده در `/fast` بدون اتصال سرویس خارجی کار می‌کند. دریافت اختیاری تصویر حساب حرفه‌ای با **Meta Business Discovery / Facebook Login** به هر سه تنظیم زیر نیاز دارد؛ ناقص بودن آن‌ها واردکردن خودکار را غیرفعال می‌کند. API رسمی با هر آیدی شخصی یا خصوصی بدون مجوز کار نمی‌کند. دریافت از سرویس‌های غیررسمی/پولی و scraping صفحه فعال نشده است.

| متغیر | کاربرد |
| --- | --- |
| `INSTAGRAM_BUSINESS_ACCOUNT_ID` | شناسهٔ عددی حساب حرفه‌ای متصل به Facebook Page و متعلق به اتصال مجاز برنامه |
| `INSTAGRAM_GRAPH_ACCESS_TOKEN` | توکن معتبر Facebook Login با مجوزهای لازم Business Discovery؛ فقط راز سمت سرور، در مرورگر یا لاگ قرار نمی‌گیرد |
| `INSTAGRAM_GRAPH_API_VERSION` | نسخهٔ صریح پشتیبانی‌شدهٔ Graph در پنل همان برنامهٔ متا، با قالب `vNN.0`؛ برنامه نسخهٔ جاری را حدس نمی‌زند |

برای دسترسی به حساب‌های بیرونی، مجوزها و نیاز به App Review/سطح دسترسی را در [راهنمای رسمی متا](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/business-discovery/) بررسی کنید. اتصال، انقضای توکن و محدودیت API باید توسط مسئول حساب مدیریت شوند. برنامه نام/بیو/شمار دنبال‌کننده را از متا کپی نمی‌کند و دادهٔ ناموجود را جعل نمی‌کند. نمونه‌های env این مقادیر را خالی نگه می‌دارند؛ محیط stage نیز به‌صورت پیش‌فرض اتصال ندارد.

## تنظیمات ابزارها

`TEST_ORIGIN` برای تست یکپارچه‌سازی باید loopback باشد؛ پیش‌فرض `http://127.0.0.1:5188` است. اسکریپت‌های تصویری ممکن است `PLAYWRIGHT_MODULE` را برای مسیر نصب ابزار بخوانند؛ این‌ها تنظیمات محصول نیستند. متغیرهای Wrangler، Miniflare و `SITES_*` در ابزارهای ساخت برای محیط میزبانی موجود مدیریت می‌شوند؛ آن‌ها را با اعتبارنامه‌های برنامه اشتباه نگیرید.

تنظیم و آزمون پنل مستقل در [مدیریت سریع](fast-admin.md) است؛ تغییر اعتبارنامهٔ آن نشست‌های پنل را باطل می‌کند و به حساب مشتری وابسته نیست.

## همگام‌سازی شیت

`EVENT_SYNC_JOB_SECRET` راز مستقل سرور/worker با حداقل ۳۲ نویسه است. `EVENT_SYNC_IMAGE_HOSTS` فهرست اختیاری نام دقیق میزبان HTTPS تصاویر، با جداکنندهٔ کاما، افزون بر Drive عمومی است. `EVENT_SYNC_JOB_ORIGIN` فقط در فرآیند worker مبدأ job را تعیین می‌کند؛ Compose مقدار داخلی `http://app:3000` می‌گذارد و در اجرای مستقل پیش‌فرض `APP_ORIGIN` است. پیوند شیت و سال شمسی در پایگاه و `/fast` نگهداری می‌شوند؛ [قرارداد کامل](event-sheet-sync.md).
