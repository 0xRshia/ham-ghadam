## Fixed in this change

1. **P1 — Product policy existed only in the request.** Active UI and direct APIs still offered purchases. New reservation requests and payment retries now return 403; old checkout links redirect. Historical records and already initiated payment verification remain available.
2. **P1 — Organizer identity depended on customer login accounts.** Name-only events could not have a public organizer profile. Added an independent registry, stable event relationships, unique normalized Instagram handles and safe public links. Account ownership remains separate. Concurrent duplicate submissions reuse the same record.
3. **P2 — Description whitespace was lost.** Paragraphs and single line breaks are preserved, text wraps safely, and expansion is offered only when the rendered text overflows.
4. **P2 — Public organizer discovery forced login.** Guests can browse public organizers and profiles; follow writes keep authentication and origin checks.
5. **P2 — Organizer writes could outlive a failed event save.** Profile creation and the first Instagram attachment now commit in the same database batch as the event. Concurrent first events share an identity; rejected media and booked-event guards leave no orphan or partial organizer changes.
6. **P2 — Early body rejection could restart/stall the local Workerd proxy.** Disabled reservations and fast-session origin failures now dispose a bounded body before replying. The HTTP integration test exercises subsequent requests on the same local worker.
7. **P2 — The Workers test harness could wait indefinitely for migration subprocesses.** Migration processes now have a 30-second process-group timeout, isolated working directories, bounded diagnostics and cleanup. Server readiness also has a total deadline and detects early process exit.

Legacy migration caveat: exact normalized name-only records are grouped because they lack a stronger identity. Two unrelated organizers can have the same name. Review legacy profiles against actual Instagram handles before deployment; newly entered handles are the authoritative unique identity. No fake telephone/customer accounts are created.

| P2 | **No global organizer correction/merge screen.** A populated Instagram handle is deliberately locked in an individual event form to avoid silently changing every linked event. | Add a dedicated curator workflow for correcting handles, renaming profiles and resolving ambiguous legacy name groups. |

The critical map dependency entry corresponds to a sanitizer/attribution issue documented in the [MapLibre advisory](https://github.com/advisories/GHSA-jrc7-96c5-q579). The lockfile also contains Next.js versions covered by the [ImageResponse advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j); no `next/og` use was found in this source. The actual app runs through vinext, so advisory impact must be assessed against the executed paths, rather than inferred from package severity alone. Updating MapLibre through the Neshan wrapper requires compatibility testing; npm reports no automatic fix for that wrapper.
