# امنیت و سطوح دسترسی

[فهرست مستندات](README.md)

این متن کنترل‌های موجود در کد را شرح می‌دهد؛ جایگزین آزمون امنیتی استقرار واقعی نیست. مرجع اصلی `lib/server.ts` و بررسی‌های داخل هر Route است.

## نشست و ورود

کوکی `hg_session` توکن تصادفی ۳۲ بایتی با نمایش هگز ۶۴ نویسه را حمل می‌کند. پایگاه داده فقط SHA-256 آن را ذخیره می‌کند. کوکی ۳۰ روز اعتبار، `HttpOnly`، `SameSite=Lax` و `Path=/` دارد و وقتی URL درخواست HTTPS باشد `Secure` می‌گیرد. پشت reverse proxy باید تشخیص HTTPS مطابق [استقرار](deployment.md) درست باشد.

کد پیامکی HMACشده، پنج دقیقه معتبر، یک‌بارمصرف و محدود به پنج تلاش است. رمز با scrypt و salt تصادفی ذخیره می‌شود. بازیابی رمز توکن پنج‌دقیقه‌ای می‌سازد و پس از ذخیره همهٔ نشست‌های قبلی را حذف می‌کند. خروج فقط نشست فعلی را حذف می‌کند. نقش‌ها از allowlist شماره در env خوانده می‌شوند.

## مجوز و Origin

| نوع عملیات | مجوز |
| --- | --- |
| کاتالوگ، رویداد منتشرشده و برگزارکننده | عمومی؛ نشست برای شخصی‌سازی اختیاری |
| پروفایل، رزرو، بلیت، علاقه‌مندی و اعلان | نشست معتبر و بررسی مالکیت |
| پنل میزبان | نشست، `isHost` و برای رکورد خاص مالکیت میزبان |
| پنل مدیریت | نشست و `isAdmin` |
| اسکنر | کلید اختصاصی رویداد در `X-Scanner-Key` |
| کار اعلان | `Authorization: Bearer` با راز مستقل |
| لغو ایمیل | HMAC محدود به حساب، نشانی و زمان تأیید |
| callback پرداخت | authority درگاه و تأیید سروری؛ بدون نشست |

اکثر عملیات نوشتن `sameOrigin` را صدا می‌زنند؛ Origin باید برابر مبدأ URL درخواست یا `APP_ORIGIN` و حتماً موجود باشد. اسکنر POST نیز این الزام را دارد. کار اعلان و لغو یک‌کلیک ایمیل استثنا هستند و اعتبارنامهٔ مستقل دارند. مستندات Swagger همان قواعد را اجرا می‌کند و مجوزی اضافه نمی‌کند. CORS عمومی برای کلاینت دلخواه در این تغییر اضافه نشده است.

## دادهٔ حساس و رسانه

اعتبارنامه‌های QR، کلید اسکنر، کوکی، رازهای env و endpoint کامل Push را در log یا مستندات عمومی نگذارید. نام، شماره، رسید، تاریخچهٔ خرید و خروجی CSV دادهٔ حساب هستند و مسیرهای آن‌ها مجوز می‌خواهند. برچسب‌ها و یادداشت مشتری مختص میزبان‌اند.

تصویر رویداد عمومی باقی می‌ماند حتی اگر فروش/انتشار رویداد متوقف شود. آواتار از مسیر عمومی با no-store خوانده می‌شود. جلد مقالهٔ پیش‌نویس فقط برای مدیر قابل خواندن است. URL ویدیوی برنامه در مرورگر بارگذاری می‌شود؛ سرور URL دلخواه میزبان را واکشی نمی‌کند.

آپلودها JPEG/PNG/WebP واقعی می‌خواهند؛ نوع باینری، ساختار، ابعاد و اندازه بررسی می‌شود. سقف یک تصویر ۵ MiB، همهٔ تصاویر رویداد ۲۰ MiB و درخواست multipart برابر ۲۱ MiB است؛ حداکثر شش تصویر گالری. SVG یا تصویر متحرک پذیرفته نمی‌شود. حداکثر هر بُعد ۱۲۰۰۰ و حاصل‌ضرب ابعاد ۴۰ میلیون پیکسل است.

## پرداخت، موجودی و اعلان

قیمت نهایی از پایگاه داده محاسبه می‌شود و مبلغ دلخواه کلاینت مبنا نیست. نتیجهٔ query در callback اثبات پرداخت نیست؛ کد verify درگاه تعیین‌کننده است. requestKey از ایجاد سفارش تکراری و SQL شرطی از فروش بیش از ظرفیت جلوگیری می‌کند. مورد paid_unfulfilled باید با سابقهٔ پرداخت واقعی پیگیری شود.

Push به نشست متصل است و حذف/انقضای نشست در زمان ارسال بررسی می‌شود؛ اشتراک معتبر قدیمی پس از خروج نباید پیام حساب قبلی بگیرد. ایمیل نیازمند نشانی تأییدشده و رضایت جداگانه است. پیام پذیرفته‌شدهٔ قبلی در سرویس خارجی را نمی‌توان با خروج یا لغو رضایت از صف آن سرویس پس گرفت.

## راه‌اندازی تولید

در تولید `TEMP_LOGIN_ENABLED`، `SEED_SAMPLE_EVENTS` و `SKIP_PAY_DEV` باید false باشند. این کلیدها صرفاً با `NODE_ENV=production` بی‌اثر نمی‌شوند. دسترسی مستقیم به درگاه backend پشت پراکسی را محدود کنید تا هدرهای هویت مبدأ/IP از مسیر مورد اعتماد برسند. پیش از هر عملیات داده‌ای پشتیبان سازگار SQLite و رسانه تهیه کنید؛ دستورها در [Docker](docker.md) هستند.
