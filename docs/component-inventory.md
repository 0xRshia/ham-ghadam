## Verified account and notification components

- `VerificationCode` (`components/evenline/verification-code.tsx`) shares the source-derived OTP cells between phone authentication/recovery and email confirmation. The existing Hmghadam security protocol uses six digits.
- `NotificationRow` and `NotificationSettings` map screen 50's icon/text/toggle pattern to seven real settings. Browser delivery is device-specific; the remaining preferences are persisted per account.
- `EmailSettings` supplies recipient verification and removal, using existing header, input, OTP and button primitives. `EmailUnsubscribe` is a signature-authorized confirmation flow for email recipients.
- `Avatar` is a shared image/initials primitive. `AvatarEditor` maps screen 45's circular photo/camera control to validated image upload. It does not use a fabricated profile photograph.
- `ProfileForm` maps screen 45's three-field layout; verified email and password states are backed by account data. `ProfileDetailsPage` retains city/biography editing as a documented domain extension.

`EventCard` now maps card/list/feature to source card variants, with a separate list `action="join" | "price"`. Home V2 uses feature and price-list variants with the existing category filter state. `EventAgenda` consumes stored session records; `EventVideo` uses source video icons with real playback, seeking, mute, fullscreen and errors. The pause state is a necessary functional extension because only the play state exists in the supplied design. `ProgramEditor` extends the existing host tools using shared inputs/buttons; it is a backend management screen beyond the consumer Figma set.
